Möbius reversible language · reversible machine
The inverse program, derived mechanically from the source by local rewriting — no analysis, no search. += becomes -=, statement order flips, if's test and assertion trade places, loops run from their exit to their entry, and push/pop, local/delocal, write/unwrite swap. Compiled and run forward on main's output, it reproduces main's input. The test suite checks this on thousands of random programs.

The idea

Ordinary computers forget. x = 0 erases whatever x held, and by Landauer's principle that erasure is where the heat of computation comes from. A reversible computer never erases anything: every step is a bijection on machine states, so the past can always be recovered from the present.

Möbius is three things built on that idea: a reversible programming language (in the Janus family), a reversible instruction set and machine (in the Pendulum/PISA family), and a compiler between them. They make possible a debugger that steps backwards by computing the previous state, without recording it. Look at the history buffer gauge: it reads 0 bytes, always.

The language

x += e   x -= e   x ^= e     // e may not mention x
x <=> y                       // swap
if c then … else … fi a       // a: exit assertion, true iff then-branch ran
from a do … loop … until c    // a true on entry, false on every re-entry
local int t = e  …  delocal int t = e'
call p(x, y)    uncall p(x, y) // uncall runs p backwards
push(x, s)      pop(x, s)      // push zeroes x; pop requires x = 0
write e         plot x, y, c   // reversible output: unwrite consumes

There is no assignment. The assertions in fi and from are what let control flow merge reversibly: arriving at a fi backwards, the assertion tells you which branch you came from. If an assertion is false at run time, the program is outside the domain of its bijection, and the machine faults.

The machine

Jumps don't overwrite pc. They add to a branch register br, and after each instruction pc += br ≠ 0 ? br : dir. Every jump lands on a matching come-from branch that cancels br, so every landing site knows where it was jumped from. dir is the direction of time. With dir = −1, each instruction executes its inverse, in reverse order. uncall is just RBRA, which flips dir and jumps into the procedure.

Expressions compile Bennett-style: every intermediate value is XORed into a fresh register (rd ^= f(ra, rb) is its own inverse), the result is used, then the whole sequence is replayed backwards to scrub the garbage. Between statements all 253 scratch registers are zero, and CHKZ verifies it. That check is also how aliasing violations are caught.

Two kinds of "backwards"

◀ / ◀◀ apply T⁻¹, the inverse of the transition function. Given the current (pc, br, dir), the previous pc is pc − (br ≠ 0 ? br : dir), and that instruction is undone. This is time travel: you see exactly the states you passed through.

⇆ main⁻¹ flips the direction bit and runs the inverse program on whatever is in memory now. Edit the globals first and it computes a pre-image: put ciphertext into TEA and it decrypts, or put a Lehmer code into perm and it builds the permutation.
